### 10. Multi-tenant device ownership (PR 86)

**Files changed:**

- `backend/app/models/device.py` - added `owner_id = Column(UUID(as_uuid=True), ForeignKey("users.id", ondelete="SET NULL"), nullable=True)`. I kept it nullable so existing unowned devices stay valid after the migration - NULL means shared/unassigned, not broken. `ForeignKey` was added to the SQLAlchemy imports alongside the existing Column types.
- `backend/migrations/003_multi_tenant.sql` - NEW. `ALTER TABLE devices ADD COLUMN IF NOT EXISTS owner_id UUID REFERENCES users(id) ON DELETE SET NULL`. The IF NOT EXISTS guard makes it idempotent. I chose ON DELETE SET NULL rather than CASCADE because losing a user account should not silently delete all their registered hardware.
- `backend/app/schemas/device.py` - added `owner_id: UUID | None = None` to both `DeviceCreate` (so an admin can assign ownership at registration time without a follow-up PATCH) and `DeviceResponse` (so callers can see who owns a device).
- `backend/app/routes/devices.py` - imported `or_` from SQLAlchemy; added `current_user: User = Depends(get_current_user)` to `list_devices`. Technicians get `q.filter(or_(Device.owner_id == current_user.id, Device.owner_id.is_(None)))` - they see their own plus unowned (shared) devices. Admins and viewers get the unfiltered query. I put the filter in the route rather than middleware so the ownership logic is explicit and auditable in one place.
- `backend/tests/test_devices.py` - NEW. Five tests: admin sees all devices, viewer sees all devices, technician sees own + unowned but not another technician's device, unauthenticated call returns 403, and `owner_id` field is present in the response body. All 5 pass; full suite 26/26.
- `suggestions/README.md` - Ticked off pagination (PR 84), all housekeeping items (PR 85), and multi-tenant device ownership (PR 86).
