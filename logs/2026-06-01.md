## Batch 1: feat/backend-auth-audit

**Branch:** feat/backend-auth-audit | **PR:** TBD | **Status:** in-progress

### What was changed and why

**`backend/app/routes/auth.py`**
- Completed GET /auth/me: decodes the Bearer token using the same python-jose + settings.secret_key pattern as create_access_token, looks up the user by the `sub` claim, returns UserResponse. I kept the same JWT decode pattern used in login rather than adding a separate dependency function, to avoid introducing new abstraction before PR 2 establishes the shared get_current_user dependency.
- Added GET /api/v1/auth/users: admin-only, paginated (skip/limit). I validate admin role from the decoded JWT and raise 403 if the caller is not an admin. Returns a list of UserResponse objects ordered by created_at desc.

**`backend/app/routes/audit.py`** (NEW)
- GET /api/v1/audit-logs: admin-only (same JWT decode + role guard), paginated with skip/limit query params. Queries the audit_log table via raw SQL (matching the raw SQL insert style in audit_service.py). Returns a list of dicts with id/user_id/action/resource/resource_id/detail/created_at. I use raw SQL here to stay consistent with how audit_service.py writes rows and to avoid adding an ORM model for a cross-cutting log table.

**`backend/app/main.py`**
- Added `from app.routes import audit` and included the router at /api/v1 prefix.

## Decisions log

| Decision | Reason |
|----------|--------|
| Use raw SQL for GET /audit-logs | Consistent with audit_service.py write side; avoids adding an ORM model for a cross-cutting log table |
| Inline JWT decode in each route (PR 1) rather than a shared dependency | Keeps PR 1 self-contained; PR 2 introduces get_current_user dependency shared across routes |
| APScheduler for demo mode rather than Celery | Avoids adding a broker dependency; APScheduler runs in-process and is already used for offline detection |
| StreamingResponse for CSV export | Avoids loading all telemetry rows into memory; safe for large datasets |
| class-based dark mode in Tailwind | Required for localStorage toggle; media-query mode cannot be overridden per user preference |
| TelemetryChart owns its own data fetch | Chart has time-range picker so it must manage from_ts; passing readings[] as a prop would force the parent to re-query on every range change |
| Python-computed cutoff for retention DELETE | Can't use INTERVAL :param syntax with SQLAlchemy bindparams; computing cutoff in Python and binding as :cutoff is cleaner |
| lifespan context manager for retention scheduler | Prevents APScheduler from starting during pytest module collection which imports main |
